# EHRSQL PostgreSQL Benchmark Files

Generated by:

```bash
python3 EHRSQL/generate_ehrsql_postgres_benchmarks.py
```

Outputs:

- `EHRSQL/ehrsql_eicu_test_postgresql.json`
- `EHRSQL/ehrsql_mimic_iii_test_postgresql.json`

Both files use only the EHRSQL `test` split and keep only rows where
`is_impossible` is false. The two datasets are intentionally not merged.

The row structure follows the LiveSQLBench/BIRD evaluation convention:

- `db_id` / `selected_database`: PostgreSQL database name
- `question` / `query`: natural-language question
- `SQL` / `gt_sql` / `gold_sql`: PostgreSQL-normalized gold SQL
- `instance_id`: stable source-prefixed EHRSQL ID
- `source_id`, `source_db_id`, `ehrsql_sqlite_query`: original EHRSQL metadata

PostgreSQL gold SQL normalization includes:

- EHRSQL official `current_time = '2105-12-31 23:59:00'`
- SQLite `datetime(...)` and `strftime(...)` translation
- SQLite join-without-ON translation to `CROSS JOIN` where applicable
- eICU `patient.age` numeric comparison casting
- selected text numeric aggregation casting
- removal of final top-level aggregate `ORDER BY ... LIMIT` where PostgreSQL rejects it

Final PostgreSQL validation against the loaded Docker databases:

- `ehrsql_eicu`: 1,152 / 1,204 gold SQL queries execute; 52 remain SQLite-specific.
- `ehrsql_mimic_iii`: 1,150 / 1,198 gold SQL queries execute; 48 remain SQLite-specific.

The remaining failures are answerable EHRSQL cases whose original SQL relies on
SQLite-specific behavior, mainly bare columns with `GROUP BY ... HAVING min(...)`
and scalar subqueries that SQLite silently truncates to one row. They should be
handled later either by manual PostgreSQL SQL repair or by marking them as
PostgreSQL-evaluation invalid, not by treating them as impossible questions.
